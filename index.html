PhishGuard

Phishing detection for Gmail with explainable AI: a Chrome extension backed by a deployed model that says why it flagged an email.

Problem

For my undergraduate Special Problem, I set out to build a phishing detector for Gmail with two priorities: keep false alarms rare, and tell the reader why an email was flagged.

What I built

A Chrome extension (Manifest V3, gmail.js) adds a scan button to Gmail. On click, it pulls 10 features from the open email: subject and body text, 5 URL statistics and 3 attachment features. A FastAPI service on Render runs a CatBoost classifier on them and returns a prediction with a SHAP explanation, and the extension turns the top SHAP features into plain-language warnings in a modal.

Key decisions

  • Matched training data to live dataTrained on the public MeAJOR email corpus, converted to Parquet, and wrote a mapping from raw MIME types to file extensions so the training data matched what the extension sees live.
  • Left sender domain outExcluded it to keep the model from overfitting to historical domains.
  • Measured what each feature group addsA 4-way feature ablation study showed URL features gave the biggest gain (F1 0.9755 → 0.9791).
  • Traded recall for fewer false alarmsSwept decision thresholds from 0.50 to 0.95 on 21,737 test emails and picked 0.85, giving up 3.3 points of recall.

Result

At the 0.85 threshold the model reaches 99.07% precision, 94.39% recall and a 0.70% false-positive rate on 21,737 test emails. The deployed API averages 71.79 ms per response in live tests, and the extension scored 84.5 on the System Usability Scale with 20 participants, in the "Excellent" range.
